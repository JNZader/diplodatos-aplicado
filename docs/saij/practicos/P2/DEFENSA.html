P2 — Defensa (D3: calidad y recorte)

Curación 50k SU+FA + bake-off de representaciones solo train (test ≥2013 no se tocó). Y de fuero no cerrada con fuzzy: el bake-off usa una etiqueta sonda (un solo token de fuero en materia).

Herencia de P1: dos unidades; campo léxico = texto en SU; no imputar materia en FA; CIVIL∩COMERCIAL es gris. Riesgos: riesgos-desde-p1.md.

1. Muestra de trabajo (por qué no 8.7k)

Consigna
Preparar datos para la fase siguiente. La validación P1 dijo: 8.7k no cubre la cola de materia.
Respuesta
Reservoir estratificado del JSONL completo, seed 42: 31.400 SU + 18.600 FA = 50.000 (mezcla ~63/37 como el censo SU+FA, no como el 50 % plano del grupo). Archivo: datos/work-sample-su-fa-50k.jsonl.gz (34 MB). En SU, materia distintas: 725 crudas / 567 tras normalizar guiones (vs 282 en 8.7k). Eso era el hueco.
Por qué
Censo: SU 483.305, FA 286.283. Un 50k proporcional ve más cola sin cargar 874k en RAM.
Teoría en este caso

Estratificar por prefijo es respetar las unidades que P1 descubrió. Un 50 % al azar (grupo) también es grande, pero no es un diseño: es “me entró en memoria”. Acá el diseño es explícito y reproducible (seed, tamaños fijos).

Error típico: seguir laburando P2 en 8.7k “porque P1 ya estaba”. La validación dijo que la cola no entra.

2. Duplicados

Consigna
Qué hacer con duplicados.
Respuesta
id-infojus y guid únicos en las 50k (0 extras). En SU, texto: 31.400 no nulos, 31.373 únicos → 27 textos repetidos. No los borramos todavía: hay que ver si el id cambia (mismo párrafo, otro expediente) antes de dropear. Para el split, la unidad candidata de NLP es el texto, no la fila: si el mismo párrafo cae en train y test, hay fuga.
Teoría en este caso

Duplicado de id ≠ duplicado de texto. El primero es un error de carga. El segundo puede ser el mismo sumario republicado. En P3, si partís por fila, dos ids con el mismo texto entrenan y examinan la misma prosa.

6. Split (ahora)

Respuesta
En SU, fecha parsea en el 100 % de las 31.400. Corte temporal: train year < 2013 (24.645) / test ≥ 2013 (6.755) ≈ 80/20 por el cuantil 0,80 de esta muestra. Las estadísticas de limpieza (stopwords, min_df de D4) solo train. No se toca test para elegir representación.
Teoría en este caso

Split aleatorio mezcla épocas: el modelo “ve el futuro” (jerga 2020 en train y test). Split por timestamp mediría carga al sistema. fecha es el reloj judicial de P1. El 80 % cae en 2013 en esta 50k; no lo copies como ley del SAIJ — se documenta el corte.

Fuga extra: los 27 textos duplicados. Antes de D4, hay que impedir que el mismo párrafo esté en los dos lados (quedarse con un id, o split por hash de texto).

7. Bake-off de representaciones (D4, train only)

Consigna
Comparar BoW, TF-IDF y embeddings; elegir una para lo que sigue. Lematizar solo si un A/B lo justifica.
Respuesta
Ganó TF-IDF (1–2 grams, min_df=5, 8k features) + LR en una sonda temporal interna: macro-F1 0,681 vs dummy estratificado 0,171. BoW+LR 0,647; BoW+NB 0,645; TF-IDF+NB 0,634. El “embedding” liviano = TF-IDF+SVD 128 (LSA) + LR: 0,606, peor. No hay sentence-transformers en el entorno: no se bajó un MiniLM. No lematizamos (sin spaCy; el costo no se justificó en 90 min). Test year≥2013 (6.755 SU) no se usó.
Por qué
Pool: SU con texto, year<2013, un solo token de fuero en materia, textos no duplicados. Fit del vectorizer: year<2010 (n=14.001). Validación: 2010–2012 (n=1.166). Clases sonda: PENAL/CIVIL/LABORAL/ADMINISTRATIVO/CONSTITUCIONAL/COMERCIAL. Por clase (TF-IDF+LR): PENAL 0,88 · LABORAL 0,78 · CIVIL 0,71 · ADMIN 0,62 · COMERCIAL 0,58 · CONSTITUCIONAL 0,53.
Teoría en este caso

BoW cuenta. TF-IDF baja lo que aparece en todos los fallos (“recurso”, “ley”) y sube lo más específico. Por eso TF-IDF le gana a BoW acá: P1 ya había mostrado que lo frecuente no es distintivo. LSA comprime a 128 dimensiones y perdió esa señal (0,61). Un embedding denso no es automáticamente mejor.

La etiqueta del bake-off no es Y final: es un token exclusivo en materia, tirando combos y OTROS. Sirve para comparar representaciones, no para reportar el TP3. CIVIL∩COMERCIAL ni siquiera entra a la sonda. Por eso CONSTITUCIONAL sale flojo: mezcla y frontera.

Error típico: ajustar TF-IDF con train+test (fuga). Error 2: elegir embeddings porque “es lo moderno” sin número. Error 3: lematizar “porque TP2 lo pide” sin A/B — la consigna pide ver el efecto, no mandar spaCy de default.

9. Receta de Y (D5) — paso detallado

Consigna
Dejar una etiqueta para P3. No copiar fuzzy ni la lista del grupo.
Respuesta
Regla, en este orden, sobre materia ya con guiones unificados:
1) tokens ∩ {CIVIL, COMERCIAL, PENAL, LABORAL, ADMINISTRATIVO, CONSTITUCIONAL};
2) si el conjunto es exactamente {CIVIL, COMERCIAL} → clase CIVIL-COMERCIAL;
3) si hay exactamente un token → esa clase;
4) si hay cero, o dos o más que no sean ese par → OTROS.
Sin rapidfuzz, sin sinónimos, sin “parece laboral”. En las 31.400 SU de la 50k: OTROS 7726 (25 %) · PENAL 5282 · CIVIL-COMERCIAL 4168 · CIVIL 4018 · LABORAL 3235 · CONSTITUCIONAL 2832 · ADMINISTRATIVO 2514 · COMERCIAL 1625.
Por qué estas reglas
P1 ya mostró que materia no es fuero: hay PROCESAL, combos y dos escrituras de CIVIL-COMERCIAL. D3 unificó guiones (725→567) y paró ahí. D4 midió representaciones con una sonda (solo un token, sin OTROS ni combos) y sacó F1 0,68: eso no es Y de entrega. D5 tiene que escribir una Y que entre a P3 entera, reproducible en 10 líneas, y que vos puedas recitar sin el notebook.
Teoría en este caso

Supervisado pide una Y antes del modelo. Si Y es un quilombo, el F1 mide el quilombo, no “el fuero argentino”. Por eso distinguimos tres cosas: (a) el fenómeno (rama del derecho), (b) el campo sucio (materia), (c) la etiqueta que inventamos nosotros con reglas. (c) no es (a).

OTROS no es una rama: es “no pude aplicar 2 ni 3”. El 25 % te dice cuánta materia no entra en seis palabras. CIVIL-COMERCIAL no es cobardía: P1 midió 689 filas con ambos tokens en 8.7k; en 50k son 4168. Si las fusionás a CIVIL, mentís COMERCIAL; si las tirás, perdés la frontera que el README pregunta.

El grupo cerró Y con fuzzy + lista + OTROS si ≥3 ramas. Eso es otra receta, no la nuestra. No la copies aunque “dé mejor”. Error típico: usar materia cruda como Y (282–567 clases inútil) o como X (fuga). Otro: cambiar la regla después de mirar el F1 de test — el test ≥2013 sigue cerrado para diseñar Y.

Cómo probarlo
CANON = ["CIVIL","COMERCIAL","PENAL","LABORAL",
         "ADMINISTRATIVO","CONSTITUCIONAL"]
def y_from_materia(m):
    if not isinstance(m, str) or not m.strip():
        return "OTROS"
    t = re.sub(r"\s*-\s*", "-", m.strip().upper())
    parts = set(re.split(r"[^A-ZÁÉÍÓÚÜÑ]+", t))
    hits = [c for c in CANON if c in parts]
    if set(hits) == {"CIVIL", "COMERCIAL"}:
        return "CIVIL-COMERCIAL"
    if len(hits) == 1:
        return hits[0]
    return "OTROS"
