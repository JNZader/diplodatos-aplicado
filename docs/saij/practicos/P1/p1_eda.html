def nonempty(s: pd.Series) -> pd.Series:
    if s.dtype == object:
        return s.notna() & s.map(lambda v: v not in ("", {}, []))
    return s.notna()

def describe_col(series: pd.Series) -> dict:
    types = series.map(lambda v: type(v).__name__ if v is not None and not (isinstance(v, float) and pd.isna(v)) else "NA")
    vc = types.value_counts()
    nested = series.map(lambda v: isinstance(v, (dict, list))).mean()
    return {
        "n_non_na": int(series.notna().sum()),
        "pct_na": round(float(series.isna().mean()), 3),
        "types": vc.to_dict(),
        "pct_nested": round(float(nested), 3),
        "nunique_approx": series.dropna().astype(str).nunique(),
    }

Hipótesis (no receta): el proyecto pide predecir fuero/rama. materia es el campo más cercano, pero:

  • hay valores que no son fuero (PROCESAL);
  • hay combinaciones (CIVIL - COMERCIAL, CIVIL-COMERCIAL con distinto separador);
  • una parte de las filas no tiene materia.

Cerrar el target hoy sería mentir. TP1 pide identificarlo, no entrenar.

Leakage a no olvidar: si el target se construye desde materia, no puede entrar materia (ni descriptores que la parafrasean) como feature cuando el README pide predecir leyendo el sumario.

Candidatos: fecha (documento), fecha-alta / fecha-mod (administrativos), timestamp / timestamp-m / timestamp-alta (epoch).

Un pico en timestamp no es, por sí solo, más fallos emitidos ese año.

6. Hallazgos preliminares (muestra, no corpus)¶

Escribir en voz alta, no como verdad del SAIJ completo:

  • Hay más de un tipo de registro en el mismo JSONL (prefijos de id-infojus + cobertura de campos distinta).
  • materia es el mejor candidato a origen del target, y está sucio (combinaciones, PROCESAL, nulos).
  • Geografía sesgada a CABA/PBA.
  • fecha a veces trae varias fechas en un string. timestamp está en milisegundos.
  • Los dos relojes no cuentan la misma historia: no usar timestamp como fecha del fallo.
